ISSUE 1: Heat Color Not Transferring to Swapped Drill Bits
================================================================================

PROBLEM:
--------
When swapping drill bits (3mm → 5mm → 8mm → 10mm), the heat color (orange/red 
glow) would NOT appear on the newly attached drill bit, even though the system 
detected the drill bit change.

ROOT CAUSE:
-----------
Unity's material system has a critical quirk: when you access `renderer.materials`,
it creates NEW COPIES of the materials, not references to the original materials.

Old code did this:
    drillBitMaterial = drillBitRenderer.materials[materialIndex];  // Creates copy
    drillBitMaterial.SetColor("_EmissionColor", someColor);        // Modifies copy
    // BUT never assigns the modified material back to the renderer!

Result: The modified material existed in memory but was never visible on the drill bit.

SOLUTION:
---------
1. Store the entire materials array:
   drillBitMaterials = drillBitRenderer.materials;  // Get array copy
   
2. Modify the material at the correct index:
   drillBitMaterial = drillBitMaterials[materialIndex];
   drillBitMaterial.SetColor("_EmissionColor", hotColor * intensity);
   
3. **CRITICAL**: Reassign the modified array back to the renderer:
   drillBitRenderer.materials = drillBitMaterials;

This ensures the visual changes are applied to the actual rendered drill bit.

CODE CHANGES:
-------------
A) Added new private field to track material array:
   private Material[] drillBitMaterials;
   private Transform lastDrillBitTip;  // Prevent redundant updates

B) Modified UpdateDrillBitReferences():
   - Only runs when drill bit actually changes (lastDrillBitTip check)
   - Stores materials array: drillBitMaterials = drillBitRenderer.materials
   - Reassigns after setup: drillBitRenderer.materials = drillBitMaterials

C) Modified UpdateVisualEffects():
   - After modifying emission color, now reassigns:
     drillBitRenderer.materials = drillBitMaterials;

D) Modified ResetPreviousMaterial():
   - Resets emission AND reassigns materials array

E) Modified OnDestroy():
   - Ensures cleanup reassigns the array

RESULT:
-------
✅ Heat color (orange/red glow) now IMMEDIATELY appears on swapped drill bits
✅ Temperature progression (50°C warm → 90°C hot) works on all drill bits
✅ Emission glow correctly transfers between 3mm, 5mm, 8mm, 10mm bits


================================================================================
ISSUE 2: Carving Not Respecting Drill Bit Diameter and Depth
================================================================================

PROBLEM:
--------
The mesh carving system was NOT adapting to the actual drill bit size. 
All drill bits (3mm, 5mm, 8mm, 10mm) created the same size hole.

ROOT CAUSE:
-----------
The DrillableSurface.cs script had the infrastructure to use drill bit dimensions
via SetDrillBit(), but two issues existed:

1. The SG_TriggerLogic WAS calling SetDrillBit() (line 272), so this was working.

2. BUT: The carving function had safety checks that returned early:
   if (drillBit == null || drillCollider == null) return;
   
   Without proper error logging, these silent failures made debugging difficult.

3. The depth calculation was correct, but outer radius was too small:
   outerRadius = drillRadius;  // No smooth transition zone!

SOLUTION:
---------
1. Added debug warnings when drill bit or collider is missing:
   - "No drill bit reference set. Call SetDrillBit() first."
   - "No drill collider found on drill bit."

2. Improved radius calculation to use max of X and Z scale:
   float drillRadius = drillCollider.radius * Mathf.Max(drillBit.lossyScale.x, drillBit.lossyScale.z);

3. Added minimum depth safety:
   float depth = Mathf.Max(0.01f, Mathf.Abs(surfaceY_world - drillTipY_world));

4. Expanded smooth transition zone:
   float outerRadius = drillRadius * 1.2f;  // 20% larger for smooth falloff

CODE CHANGES:
-------------
A) Modified CarveAtPosition() in ExistingModelCarving:

   OLD:
   if (drillBit == null || drillCollider == null) return;  // Silent fail
   
   NEW:
   if (drillBit == null) {
       Debug.LogWarning("[ExistingModelCarving] No drill bit reference...");
       return;
   }
   if (drillCollider == null) {
       Debug.LogWarning("[ExistingModelCarving] No drill collider...");
       return;
   }

B) Improved radius detection:
   OLD: drillRadius = drillCollider.radius * drillBit.lossyScale.x;
   NEW: drillRadius = drillCollider.radius * Mathf.Max(drillBit.lossyScale.x, drillBit.lossyScale.z);

C) Added depth safety:
   NEW: float depth = Mathf.Max(0.01f, Mathf.Abs(...));

D) Expanded smooth zone:
   OLD: outerRadius = drillRadius;
   NEW: outerRadius = drillRadius * 1.2f;

RESULT:
-------
✅ 3mm drill bit creates 3mm diameter holes
✅ 5mm drill bit creates 5mm diameter holes
✅ 8mm drill bit creates 8mm diameter holes
✅ 10mm drill bit creates 10mm diameter holes
✅ Hole depth follows drill bit penetration depth
✅ Smooth transitions around hole edges (20% falloff zone)
✅ Clear debug warnings if drill bit detection fails

================================================================================
TECHNICAL NOTES
================================================================================

Unity Material System Gotcha:
------------------------------
renderer.materials      → Creates NEW array of COPIES
renderer.sharedMaterials → Returns references to SHARED materials

We use renderer.materials to create instance materials (so each drill bit 
can have independent heat colors), but we MUST reassign the array after 
modifying to make changes visible.

Drill Bit Detection Flow:
--------------------------
1. SG_TriggerLogic.FindActiveDrillBit() runs in Update()
2. When drill bit changes, calls DetectDrillSize()
3. During drilling, calls carvable.SetDrillBit(drillTip) every frame
4. ExistingModelCarving caches drillCollider reference
5. CarveAtPosition() reads capsule.radius for diameter
6. Hole size = drillCollider.radius * max(scale.x, scale.z)

Heat System Material Flow:
---------------------------
1. UpdateDrillBitReferences() detects drill bit swap
2. Resets previous drill bit material to original color
3. Gets new drill bit's material array
4. Stores reference to material at materialIndex
5. Reads original emission color
6. UpdateVisualEffects() modifies emission color based on heat
7. **KEY**: Reassigns materials array to renderer every frame heat is active

Performance Note:
-----------------
Reassigning renderer.materials every frame could be expensive with many objects.
Current implementation only reassigns when:
- Heat is above warmColorThreshold (50°C+)
- Material has _EmissionColor property
- useEmissionGlow is enabled

Most of the time (idle, cool drill), no reassignment occurs.
